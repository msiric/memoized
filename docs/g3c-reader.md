# G3C reader support

The native autocomplete remains an ordinary free problem, not an execution
engine. The complete question owns its requirements and local setup. Its
optional primary link appears on the free lesson preview only when the exact
five original identities and the new native record exist together.

For that six-record lesson only, the new task moves last while all five original
rows keep their incoming relative order. The older five-row state and unexpected
shapes are returned unchanged. Global problem-bank sorting is unaffected.

The lesson's approved legacy fragments use plain literal headings:

```html
<h2 id="introduction-to-coding-interviews">Frontend interview formats</h2>
```

The MDX pipeline normalizes only a static h2 with one valid literal ID and
nonempty plain-text children into the same heading path used by Markdown.
The ordinary h2 renderer, section exports and sidebar therefore share the same
visible title and ID. Other JSX is not made safe or authorized by this helper:
the G3C publisher must independently enforce its exact ID/title pairs and reject
expressions, extra attributes and unknown components. Markdown slug generation
is unchanged.

JSX and TSX fences use distinct labels, as do HTML and CSS. They remain inert
source displayed with the existing tabs and copy controls. The renderer does not
evaluate a learner's program. Existing labels and G3B's setup remain unchanged.
